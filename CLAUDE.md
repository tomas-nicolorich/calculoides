## Agent dispatch rule

**Dispatch to a background agent when**: reading 3+ files, OR a single file >200 lines, OR the work is self-contained (clear inputs → output file, no back-and-forth needed).
**Inline when**: 1-2 small files, tight back-and-forth needed, or the result directly drives the next tool call.

### Commands
*~45,000 tokens/session saved*
- `rtk find` cannot handle compound predicates (`-not`, `-exec`, `-o`, `\(...\)`) — always fails with `Error: rtk find does not support compound predicates or actions`. Use plain `find` with a single `-name`/`-type` test, or pipe through `grep -v node_modules` instead of combining predicates.
- `npm test -w frontend -- --testPathPattern=X` and `--reporter=verbose` piped to `tail` frequently truncate mid-output or hide the actual failing assertion; prefer `npm test -w frontend -- "<TestName>" 2>&1 | grep -A 30 "FAIL\|<test description>"` to land on the failure directly.
- `git commit` inside `.claude/worktrees/*` frequently fails the first attempt because staged files include paths outside the worktree's actual diff (leftover stash state) — run `git status --short` and `git diff --cached --name-only` before retrying `git commit`, and use `git restore --staged .` then re-add only the intended files rather than re-running the same `git add && git commit` repeatedly.

### Worktrees
*~26,562 tokens/session saved*
- Worktrees live at `.claude/worktrees/<name>/`. Inside a worktree session `cd api` fails because CWD is already the worktree root. Set `ROOT=/home/tom/projects/calculoides/.claude/worktrees/<name>` and navigate with absolute paths: `cd "$ROOT/api"`.
- After entering a worktree, run `git rebase origin/develop && npm install --workspaces` before any work — the worktree starts from HEAD and may not be rebased or have dependencies installed.
- Background/subagent sessions cannot Edit files in the shared checkout directly — the first Edit attempt always errors with "This background session hasn't isolated its changes yet. Call EnterWorktree first". Call EnterWorktree before the first Edit in any background/subagent task, not after hitting the error.

### Fallow Gate
*~1,700 tokens/session saved*
- The pre-commit hook runs `fallow audit --base <upstream> --quiet --gate-marker pre-commit`. In a worktree with no upstream, the gate falls back to `main` and may over-report. Fix: `git branch --set-upstream-to origin/develop <branch>` before committing.
- When the gate still blocks after setting upstream, run `fallow audit --base origin/develop --quiet --explain --gate-marker pre-commit` directly to diagnose. Use `origin/develop` (the remote tracking ref), not just `develop`.
- Never use `--no-verify` to bypass the gate; fix reported issues or add false positives to `.fallowrc.json`.
- Committing only docs/config/`.specify` files (no staged `.ts`/`.tsx`) still triggers the hook's `npm run typecheck` (turbo) and prints `lint-staged could not find any staged files matching configured tasks` plus a turbo `No tasks` warning — this is expected, not a real failure; the commit proceeds unless fallow itself blocks.

### Test Commands
*~800 tokens/session saved*
- Run all tests from repo root: `npm test`. Workspace-specific: `npm test -w api` or `npm test -w frontend`. TypeScript check: `npm run typecheck` (all) or `npm run typecheck -w api`.
- API integration tests require Supabase env vars loaded via `api/vitest.config.ts`. Frontend tests need `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY` configured in `frontend/vite.config.ts` or `.env.test` at repo root.
- `.env.test` is in `.gitignore` — do not create it for committed test config. Put test env vars directly in `api/vitest.config.ts` (`test.env`) and `frontend/vite.config.ts` (`test.env`) instead.

### Supabase / Prisma TLS
*~1,200 tokens/session saved*
- The recurring 'self-signed certificate in certificate chain' error on Vercel is caused by `sslmode=require` in `DATABASE_URL`. Prisma handles TLS separately via `DATABASE_CA_CERT`. The fix: remove `sslmode=require` from the URL, or switch the env var to `POSTGRES_PRISMA_URL` (which includes `?pgbouncer=true` for the pooler on port 6543). Do not add `rejectUnauthorized: false` — that disables TLS verification in production.
