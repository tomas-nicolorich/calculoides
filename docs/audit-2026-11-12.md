# Codebase audit — 2026-11-12

A full pass over the repository looking for code that is broken, inconsistent,
inefficient, or no longer needed. The fixes below shipped with this document.
The open items are the backlog for the next rounds of work.

Verified after the fixes: `bun run lint`, `bun run typecheck`, `bun run test`
(576 tests) and `fallow dead-code` pass. `next build` and the running app were
not exercised.

## Fixed

- **Transfers ignored on the dashboard and savings page.** `summary.ts` and
  `savings.ts` matched transfers by `category_members` id instead of group
  member id, so no transfer ever matched. Per-member `budgeted` and
  `remainingQuota` never moved.
- **Editing a category deleted its transfers.** `updateCategory` deleted every
  member link on each save, and transfers cascade from those links. It now
  leaves links alone unless a member subset is sent, and then removes only the
  members who left it.
- **Cross-group read.** `listTransfers` let a `categoryId` query param replace
  the group filter, so a member of one group could list another group's
  transfers.
- **Cross-group write.** `updateExpense` accepted a category or payer from
  another group.
- **Archived transfers still counted** in category balances (`budget.ts`).
- **Failed deletes and income saves looked successful.** Server Actions return
  `{ ok: false }` and never throw, so the existing error UI for deleting
  expenses or transfers and saving incomes never showed.
  `app/_data/throw-on-failure.ts` wraps those five mutations.
- **Membership check loaded every group with all members** on each page and
  API call. It is now one count query (`GroupService.hasAccess`).
- **Removed:**
  - the dashboard copy of `InlineAllocationEditor` (only its own test imported it)
  - `BudgetService.listCategories`, `ExpenseService.getExpensesByCategory`,
    `ExpenseService.archiveGroupExpenses`
  - the unused `RecentExpense` and `CategoryBalance` types in `shared`
  - `supabase` and `cross-env` dev dependencies
  - `.npmignore` and `.dockerignore`
  - the `test:local` script and the `turbo run test` / `turbo run lint` calls
    that ran nothing
  - the unused `@` alias in the vitest config
- **Lint now covers `shared/`**, which it previously skipped.
- **Docs:** README, CLAUDE.md and the PR template no longer point at
  `frontend/`, `api/`, `CONTEXT-MAP.md` or the pre-archive openspec path.

## Open items

### Missing features

1. **Invitations, Archive and ownership transfer have no UI.** The Server
   Actions exist in `lib/actions/group.ts` (`archive`, `undoArchive`,
   `transferOwnership`, `invitationCreate`, `respondInvite`, `read`) but
   nothing calls them. Invitation emails link to `/invite/<token>`, which has
   no route. A group cannot gain a second member from the app.
   `InvitationService.getPendingInvitationsForUser` is unused for the same
   reason.
2. **`/members` has no nav entry.** Only the page itself links to it.
   `NavItem["key"]` lists `"members"` but `NAV_ITEMS` has no such item.

### Domain and data model

3. **A category's first transfer turns it into a Member Subset.**
   `provisionUnrestrictedMembers` (`transfer.ts`) creates member links for all
   current members, and every reader treats "has links" as "restricted", so
   anyone joining later is excluded. The cause is that `Transfer` foreign keys
   point at `category_members`. Fixing it needs a schema change (point the
   keys at `group_members`, or add an explicit restricted flag).
4. **Two period definitions.** The summary and the savings affordability
   ceiling count the current calendar month (`date >= startOfMonth`). Category
   cards count everything not archived. They disagree for unarchived items
   from earlier months. The transfers list also shows archived transfers while
   the expenses list hides archived expenses.
5. **"Delete all expenses" also deletes archived ones**, and any member can
   run it. The glossary says archived records are immutable. "Delete all
   transfers" behaves the same way.

### Error handling

6. **`BudgetCategories` ignores failed results** for create, update, delete
   and transfer. Create and update leave the dialog open with no message.
   Delete and transfer close as if they succeeded. Each needs an error
   display. `throwOnFailure` fits delete and transfer once the callers catch;
   create and update already check `result.ok` and only lack the message.

### Configuration and tooling

7. **`DATABASE_URL` vs `POSTGRES_PRISMA_URL`.** `lib/prisma.ts` reads the
   first, `prisma.config.ts` the second. Both are documented in the README;
   one name would be simpler.
8. **Playwright points at a missing `e2e/` directory**, so `test:e2e:next`
   finds no tests. Add specs or drop the config and the dependency.
9. **Leftover duplication and stale files:**
   - `dev:local`, `dev:next`, `build:next`, `test:next`, `lint:next` and
     `typecheck:next` duplicate the main scripts.
   - `ExpenseForm` exists twice (dashboard and expenses), deliberately per
     ADR-2 in `openspec/changes/archive/2026-08-18-nextjs-migration-ui-fixes/design.md`.
   - `.prettierignore` exists with no Prettier installed.
   - `getAuthenticatedUser` is duplicated in `lib/actions/group.ts` and
     `lib/actions/user.ts`.
   - `.fallowrc.json` ignores `next-env.d.ts`, which only exists after a build.

### Smaller server issues

10. - `GroupService.removeMember` runs the ownership handover outside its
      transaction (`handleOwnershipSuccession` uses the global client).
    - `createCategory` and `updateCategory` don't check that `memberIds`
      belong to the group.
    - API routes pass an unvalidated `limit` / `offset` to Prisma (`NaN` and
      unbounded values reach the query).
    - The invitation link defaults to `http://localhost:5173`, the old Vite
      port.
    - `getAuthenticatedUserId` is exported from a `"use server"` file, which
      makes it a public endpoint.
    - `TransferService` throws `"Category not found."` (with a period), which
      `lib/server/errors.ts` does not map, so it surfaces as a 500.
    - `respondInvite` can mark an already accepted invitation as declined, and
      compares emails case-sensitively.
    - The summary's `recentTransfers` lacks the `categoryId` and
      `categoryIcon` fields that `DashboardSummarySchema` declares, and the
      server-prefetched summary carries `Date` objects where the API route
      returns ISO strings.
    - Recent expenses fall back to `"Unknown"` for a payer without a name,
      while every other place falls back to the email.

### Comments

11. **Many comments cite deleted `frontend/` and `api/_src/` paths.** They
    were left in place; CLAUDE.md now says they describe where code was
    ported from.
