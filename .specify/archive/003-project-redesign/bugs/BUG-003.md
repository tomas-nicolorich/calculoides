**Type**: Untested flow

## Description
Every time a call to the backend is made, it happens twice. This is visible in the network tab and can lead to performance issues or incorrect data processing if the endpoints are not idempotent.

### spec.md
- **Affected user story**: US1 - Dashboard Overview (Priority: P1), US2 - Expense Management (Priority: P2)
- **Affected requirements**: SC-001 (Performance: renders in < 2 seconds)
- **Gap identified**: The specification does not explicitly define idempotency or duplicate request handling for frontend hooks, nor does it account for React 18/19 Strict Mode behavior which often triggers double-effects during development.

### plan.md
- **Affected sections**: Technical Context (Performance Goals), Project Structure (FSD folders)
- **Impact**: The performance goal (SC-001) might be compromised by redundant network traffic. The implementation of API client hooks needs to be reviewed for proper lifecycle management.

### tasks.md

- **False completions**: T006 (Marked complete, but logic is producing duplicate calls)
- **Missing tasks**: New task needed to investigate and fix request deduplication or lifecycle double-triggering.

## Root Cause Analysis
This is likely an implementation oversight or an untested flow. Common causes include:
1. **React Strict Mode**: In development, React mounts components twice to help identify side-effect issues.
2. **Hook Lifecycle**: `useEffect` or custom hooks in `dashboardHooks.ts` might be triggering twice due to missing dependency arrays or race conditions.
3. **Provider Over-nesting**: The `ThemeProvider` or other app-level providers might be causing unnecessary re-renders that re-trigger data fetching.
