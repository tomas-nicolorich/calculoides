# Bug Report: Persistent Low Contrast on Form Select and Option Elements in Dark Mode

**Type**: Implementation drift
**Severity**: High
**Feature**: 003-project-redesign
**Reported**: 2026-05-29
**Status**: Patched
**Patched**: 2026-05-29

## Description
When Dark Mode is enabled, interactive form `<select>` elements and their child `<option>` elements throughout the application suffer from poor contrast, making form options virtually unreadable. Although BUG-013/T047 was implemented to address theme-aware form contrast, several forms (such as Log Expense, Budget Transfer, and Create Category dialogs) continue to have unreadable dropdown selections.

Specifically, when a `<select>` element has custom inline styles like `bg-transparent` or explicitly specified backgrounds, they override the base-layer stylesheet rule in `index.css`. Because these components lack explicit theme-aware text-color classes (e.g., `text-slate-900 dark:text-slate-100`), they inherit white text in Dark Mode, which clashes against browser-default white backgrounds for native `<option>` dropdown dropdowns, creating an illegible white-on-white text state. This issue is visible in the provided reference image `@docs/123506.png`.

## Root Cause Analysis
1. **CSS Class Specificity Overrides**: Tailwind v4's base-layer rules in `index.css` (e.g. styling tag selectors like `select, textarea, option`) are lower in specificity than Tailwind class names defined directly on the elements. Multiple forms use inline styles like `bg-transparent` which completely disable the base dark background styles but fail to provide an explicit theme-aware text color utility class, triggering default user-agent behaviors.
2. **Native Dropdown Options Styling**: Styling standard `<select>` and `<option>` tags in modern browsers is famously inconsistent. When a parent select inherits white text (`text-foreground`) in Dark Mode, native Chrome/Edge dropdown lists often preserve a light backdrop but inherit the white text color, rendering options as white text on a white background.
3. **Lack of Reusable Component Abstraction**: While text-based inputs use a robust custom `<Input>` element to guarantee high contrast, select elements were left as raw HTML elements with ad-hoc classes, leading to inconsistent behavior and design drift.
