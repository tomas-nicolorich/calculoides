# Bug Report: Dark Mode Form Input Contrast and Missing Theme Tokens

**Patched**: 2026-05-29

## Description
When Dark Mode is enabled, interactive form inputs (such as `<input>` and `<select>` elements) throughout the application have extremely poor contrast. Specifically, the text entered into form fields remains dark (slate-900 or browser default black), which on dark background containers (slate-950 or slate-800) makes the input text virtually illegible and very difficult to read. 

This issue is visible in the provided reference image `@docs/123506.png` and affects forms such as Log Expense, Create Category, Set Income, and Profile Settings.

## Root Cause Analysis
There are two main causes for this issue:
1. **Implementation Drift from Blueprint CSS**: The CSS implementation in `frontend/src/app/index.css` drifted from the styling system planned in `blueprint.md` (lines 83-111). The blueprint defined crucial theme tokens such as `--color-card`, `--color-border`, `--color-text-main`, and `--color-text-muted` under both `.light` and `.dark` blocks. The deployed `index.css` only styles the `body` background, leaving these utility tokens undefined.
2. **Missing Input Text Color Overrides**: The custom `<Input>` element in `shared/ui/index.tsx` and standard `<select>` dropdowns across other forms are styled with transparent backgrounds (`bg-transparent`) but do not explicitly specify an active text color (e.g., `text-slate-900 dark:text-slate-100`). In dark mode, these inputs inherit a dark background from their containers but fallback to dark text colors due to browser-specific user-agent stylesheets, causing severe contrast failures.
