# Bug Report: 404 Errors on Dashboard API Endpoints

**Type**: Implementation drift
**Severity**: Critical
**Feature**: 003-project-redesign
**Reported**: 2026-05-28

## Description
When opening a group from the "My Groups" view, the dashboard fails to load because the API requests to `/api/transactions/categories-list` and `/api/transactions/summary` return 404 Not Found. This prevents the user from seeing their financial overview, categories, or recent activity.

## Artifact Traceability

### spec.md
- **Affected user story**: User Story 1 - Dashboard Overview
- **Affected requirements**: 
    - **FR-007**: My Groups selection to change active dashboard context.
    - **FR-012**: Remaining Balance card (depends on `/summary`).
    - **FR-014**: Budget Categories card (depends on `/categories-list`).
- **Gap identified**: The spec assumed underlying APIs "already exist" but did not specify the exact endpoint paths. This led the implementation to guess the paths incorrectly.

### plan.md
- **Affected sections**: Technical Context
- **Impact**: The API client hooks in the frontend were implemented with a nested REST path structure (`/api/transactions/[action]`) that is incompatible with the backend's action-dispatch architecture (`/api/transactions?action=[action]`) and the logical rewrites defined in `vercel.json`.

### tasks.md
- **Affected tasks**: 
    - **T006**: "Implement API client hooks for fetching dashboard and group data in `frontend/src/shared/api/dashboardHooks.ts`"
- **False completions**: T006 is marked as complete but contains invalid endpoint paths that cause 404 errors.
- **Missing tasks**: New task required to align `dashboardHooks.ts` with either the `vercel.json` rewrites (e.g., `/api/summary`) or the backend dispatch parameter (`?action=summary`).

## Root Cause Analysis
The frontend implementation of `dashboardHooks.ts` assumes the backend routes are nested under `/transactions/`, such as `/api/transactions/summary`. However, the backend is structured such that `transactions.ts` is a single file mounted at `/api/transactions`, using a `dispatch` utility that routes based on an `action` query parameter. While `vercel.json` provides logical aliases like `/api/summary`, the frontend code bypassed these and called the nested structure directly, resulting in 404s.

## Recommended Fix
1. Run `/speckit.bugfix.patch` to update `tasks.md` (reopen T006) and clarify API paths in `spec.md`.
2. Run `/speckit.bugfix.verify` to confirm consistency.
3. Resume `/speckit.implement` to update `frontend/src/shared/api/dashboardHooks.ts` to use correct logical paths (e.g., `/summary`, `/categories`, `/expenses`, `/transfers`) which are supported by the `vercel.json` rewrites.
