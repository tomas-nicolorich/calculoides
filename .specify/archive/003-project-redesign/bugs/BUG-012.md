# Bug Report: ESM/CJS Conflict in Vercel Deployment for env.ts

**Type**: Implementation drift
**Severity**: Critical
**Feature**: 003-project-redesign
**Reported**: 2026-05-29
**Status**: Patched
**Patched**: 2026-05-29

## Description
When the application is deployed to Vercel, API requests (such as `GET /api/groups`) fail with a 500 Internal Server Error. The Vercel logs show a `SyntaxError: Identifier '__filename' has already been declared` in `/var/task/api/src/env.js`.

This occurs because `api/src/env.ts` uses ESM-specific code to define `__filename` and `__dirname`:
```javascript
const __filename = fileURLToPath(import.meta.url);
const __dirname = path.dirname(__filename);
```
When Vercel compiles this file into CommonJS, the runtime already provides `__filename` and `__dirname` globally in the module wrapper. Redeclaring them with `const` causes a fatal syntax error that prevents the backend from initializing.

## Root Cause Analysis
The root cause is an implementation error in `api/src/env.ts` where ESM syntax (`import.meta.url`) and CJS workarounds are mixed without explicitly configuring the project as `"type": "module"`. When Vercel bundles the application as CommonJS, `__filename` is already defined in the module scope, causing the `const __filename` declaration to crash the application.
