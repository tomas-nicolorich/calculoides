# Bug Report: Expense Creation Null Constraint Violation

**Type**: Implementation drift
**Severity**: High
**Feature**: 001-calculoides-core-app
**Reported**: 2026-05-15

## Description
When creating an expense via `POST /api/expenses`, the system fails with a Prisma error `P2011` (Null constraint violation). The trace points to `prisma.expense.create()` in `ExpenseService.logExpense`. This occurs because the implementation attempts to use the authenticated `User ID` directly as the `payerId`, but the `Expense` model requires a `GroupMember ID`.

## Artifact Traceability

### spec.md
- **Affected user story**: User Story 2 — Budgeting & Spending
- **Affected requirements**: FR-003 (System MUST allow members to log expenses with description, amount, date, and payer.)
- **Gap identified**: The specification does not explicitly define how the "Payer" identity is resolved from the authenticated user session to the specific group membership record required by the data model.

- **Impact**: The service layer design for expense logging is underspecified. It must account for resolving the `userId` + `groupId` (from `categoryId`) into a `GroupMember.id`.

## Root Cause Analysis
In `api/expenses.ts`, the code passes `req.user.id` (the Auth User UUID) as the `payerId` to `ExpenseService.logExpense` when no explicit `payerId` is provided in the request body. However, the database schema defines `Expense.payerId` as a foreign key to `GroupMember.id`. Passing a `User.id` results in a database-level constraint failure. The manifestation as a `Null constraint violation (P2011)` instead of a `Foreign Key violation (P2003)` suggests that the value being passed is being rejected or interpreted as null by the driver when it fails to find a matching record, or that the `categoryId` and `payerId` relationship is failing in a way that Prisma reports as a null constraint.

## Recommended Fix
1. Run `/speckit.bugfix.patch` to update spec artifacts to clarify Payer resolution requirements.
2. Run `/speckit.bugfix.verify` to confirm consistency across the data model and services.
3. Resume `/speckit.implement` to:
    - Modify `ExpenseService.logExpense` to resolve the `GroupMember` record for the given `userId` and the `groupId` associated with the `categoryId`.
    - Add validation to ensure the payer belongs to the group where the expense is being logged.
