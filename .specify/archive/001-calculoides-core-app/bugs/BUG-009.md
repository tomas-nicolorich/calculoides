# Bug Report: Budget Category Visibility Inconsistency

**Status**: Patched
**Patched**: 2026-05-14
**Type**: Implementation drift
**Severity**: High
**Feature**: 001-calculoides-core-app
**Reported**: 2026-05-14

## Description
When a user creates a budget category, the "Overview" section correctly reflects the added budget amount in the group total. However, the "Budget" tab displays "No categories found", and categories are unavailable when attempting to log an expense. This indicates a discrepancy between how category totals are aggregated and how category lists are retrieved or displayed.

## Artifact Traceability

### spec.md
- **Affected user story**: User Story 2 — Budgeting & Spending
- **Affected requirements**: 
    - **FR-004**: "System MUST display a dashboard showing... category status. All categories MUST be visible to all members of the group."
    - **Acceptance Scenario 1 (US2)**: "Then all members should see their individual share..."
- **Gap identified**: The implementation fails to fulfill the requirement that all categories must be visible to all members. It likely applies an incorrect filter (possibly filtering by `CategoryMember` association) in the list view that isn't applied in the summary/overview view.

### plan.md
- **Affected sections**: Technical Context (Supabase RLS enforcement, React (FSD) frontend logic)
- **Impact**: Verification of RLS policies on the `categories` table and the data fetching logic in the `BudgetService` and frontend features is required.

### tasks.md
- **Affected tasks**: 
    - **T025**: Create Category management and Expense logging endpoints in api/src/
    - **T027**: Create Category list and Expense entry UI in frontend/src/features/budget/
- **False completions**: 
    - **T025**: The endpoints are likely returning an incomplete list of categories.
    - **T027**: The UI components are not correctly displaying all categories available to the group.
- **Missing tasks**: 
    - T065: Audit and fix RLS policies for `categories` table to ensure group-wide visibility.
    - T066: Verify `BudgetService.listCategories` returns all categories for the group regardless of explicit membership.

## Root Cause Analysis
The root cause is likely an implementation error where the query for listing categories joins on or filters by `CategoryMember` (explicit membership), whereas the spec requires all categories to be visible to all group members by default. The "Overview" section probably performs a simple sum over all categories in the group, which is why it reflects the correct total, while the list view is over-constrained.
