# Bug Report: Persistent Loading Spinner on Savings Goal Update

**Type**: Implementation drift
**Severity**: Medium
**Feature**: 001-calculoides-core-app
**Reported**: 2026-06-06
**Status**: Patched
**Patched**: 2026-06-06

## Description
When updating a savings goal contribution or metadata, the application correctly sends the update to the server and updates the local UI state with the new values. However, the loading spinner that appears during the request never disappears, leaving the UI in an interactive but visually blocked or busy state. A full page reload is required to clear the spinner.

## Root Cause Analysis
The issue likely resides in the frontend mutation logic for updating savings goals. While the `onSuccess` callback is correctly triggering UI updates and data re-validation, the loading state (likely a local `useState` or a TanStack Query `isLoading`/`isPending` flag) is not being correctly resolved or the component is stuck observing an old state. This is a classic "missing finally block" or state synchronization error where the "busy" flag is never set back to false after the promise settles.
