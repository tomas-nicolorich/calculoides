# Bug Report: Foreign Key Constraint Violation in Savings Goal Contribution Upsert

**Type**: Untested flow
**Severity**: Critical
**Feature**: 001-calculoides-core-app
**Reported**: 2026-05-15
**Status**: Patched
**Patched**: 2026-05-15

## Description
When attempting to adjust a savings goal contribution, the application fails with a Prisma error `P2003` (Foreign key constraint violation). This occurs specifically in the `SavingsService.upsertContribution` method when invoking `prisma.savingsGoalContribution.upsert()`. The violation is on the `savings_goal_contributions_goalId_fkey` constraint, suggesting that the `goalId` provided does not exist in the `SavingsGoal` table at the time of the database call.

```text
PrismaClientKnownRequestError: 
Invalid `prisma.savingsGoalContribution.upsert()` invocation:
Foreign key constraint violated on the constraint: `savings_goal_contributions_goalId_fkey`
```

## Root Cause Analysis
The root cause is a lack of defensive validation in `SavingsService.upsertContribution`. The `upsert` operation in Prisma requires that the records referenced by foreign keys already exist. If the UI passes a stale or incorrect `goalId`, the database enforces referential integrity and rejects the operation. This was likely missed during TDD because the tests probably only used valid, recently-created IDs.

    - Improve error handling in the API controller to return a 404 if the goal is missing instead of letting the 500 error bubble up from the database.
