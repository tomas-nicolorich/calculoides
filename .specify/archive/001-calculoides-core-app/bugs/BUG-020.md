# Bug Report: Missing Savings Goal Contribution Overrides

**Type**: Implementation drift
**Severity**: Medium
**Feature**: 001-calculoides-core-app
**Status**: Patched
**Patched**: 2026-05-15

## Description
The user is unable to modify individual member contribution amounts in the savings goal section. While the `SavingsGoalList` component displays overrides if they exist in the data, it provides no interface (inputs, sliders, or buttons) to create or update these overrides. Additionally, the recalculation of the projected completion date based on these overrides is not visible or triggered from the UI.

## Artifact Traceability

### spec.md
- **Affected user story**: User Story 3 — Savings Goals & Proportional Contributions
- **Affected requirements**: 
    - FR-006: "Any group member MUST be able to override their own or any other member's contribution. If contributions are overridden, the system MUST recalculate the projected date and display the variance from the original target date."
    - Acceptance Scenario 2: "Given an active savings goal, When a member overrides their contribution amount, Then the app must recalculate and display the new projected completion date."
- **Gap identified**: None. The specification correctly defines the requirement.

### plan.md
- **Affected sections**: Technical Context, Phase 5 implementation.
- **Impact**: The UI architecture needs to support stateful editing of member contributions within the `SavingsGoalList` or a dedicated detail view. The logic for "Dynamic Deadline" mentioned in the clarifications needs to be fully integrated into the frontend.

### tasks.md
- **Affected tasks**: 
    - T031: Create Savings Goal CRUD and override endpoints in api/src/
    - T032: Implement Savings Goal widget in frontend/src/features/savings/
- **False completions**: 
    - T032 is marked as complete but fails to implement the "override" UI controls.
    - T031 is marked as complete, but its functionality for handling overrides needs to be verified against the UI requirements.
- **Missing tasks**: 
    - Implement contribution override UI in `SavingsGoalList`.
    - Implement variance display (variance from original target date).

## Root Cause Analysis
Implementation focused on the display of existing data and initial goal creation, neglecting the interactive "override" requirement and the associated date recalculation feedback loop in the UI.

## Recommended Fix
1. Run `/speckit.bugfix.patch` to update spec artifacts (optional, to add more explicit UI success criteria).
2. Run `/speckit.bugfix.verify` to confirm consistency.
3. Resume `/speckit.implement` to:
    - Add an "Edit Contributions" mode to `SavingsGoalList`.

    - Connect these inputs to the `T031` override endpoint.
