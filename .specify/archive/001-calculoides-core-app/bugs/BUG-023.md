# Bug Report: Missing User Names in Savings Goal Section

**Type**: Implementation drift
**Severity**: Medium
**Feature**: 001-calculoides-core-app
**Reported**: 2026-05-15
**Status**: Patched
**Patched**: 2026-05-15

## Description
When viewing the savings goal section, member names are displayed as "Unknown User" for all group members. This occurs despite FR-015 mandating consistent use of the `name` property for display across the entire UI.

## Artifact Traceability

### spec.md
- **Affected user story**: User Story 3 - Savings Goals & Proportional Contributions
- **Affected requirements**: FR-015 (Consistent user name display), FR-006 (Recalculate and display contributions)
- **Gap identified**: The implementation of Savings Goals (US3) either lacks the necessary name hydration in API responses or the frontend component is not correctly accessing the `name` property, failing to comply with the global requirement established in BUG-014.

### plan.md
- **Affected sections**: Phase 5: User Story 3 - Savings Goals (Technical Context)
- **Impact**: The Technical Context section "Constraints" mandates that frontend components strictly use the `User.name` property. The Savings Goal implementation needs to be brought into compliance with this constraint.

### tasks.md
- **Affected tasks**: 
    - T032: Implement Savings Goal widget in frontend/src/features/savings/
    - T031: Create Savings Goal CRUD and override endpoints in api/src/
    - T077: Update API responses to ensure name is always included in member/user relations for hydration (BUG-014)
- **False completions**: T077 was marked as complete but clearly did not cover the Savings Goal related endpoints or relations.
- **Missing tasks**: 
    - [US3] Ensure `SavingsService` includes member names in goal/contribution objects.
    - [US3] Update `SavingsGoalList` and related components to use the `name` property from the hydrated member objects.

## Root Cause Analysis
Implementation drift. While BUG-014 introduced FR-015 to fix this issue globally, the specific implementation of User Story 3 (Savings Goals) was either completed before this requirement was fully propagated or the hydration logic was not applied to the specific database queries used by the Savings Goal endpoints.

## Recommended Fix
1. Run `/speckit.bugfix.patch` to update spec artifacts (add SC or refine FR if needed, though FR-015 is already quite clear).
2. Run `/speckit.bugfix.verify` to confirm consistency.
3. Resume `/speckit.implement` to apply the code fix:
    - Update `api/src/services/savings.ts` to include `member.user.name` in queries.
    - Update `frontend/src/features/savings/` to use the `name` property.
