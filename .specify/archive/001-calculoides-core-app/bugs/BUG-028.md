# Bug Report: Incomplete Remainder Absorption in Financial Calculations

**Type**: Implementation drift
**Severity**: Medium
**Feature**: 001-calculoides-core-app
**Reported**: 2026-05-28
**Status**: Patched
**Patched**: 2026-05-28

## Description
The user reports that percentages are not rounded when they should be, and the "Remainder Absorption" logic (assigning the rounding difference to the member with the highest percentage/income) is missing or failing. This violates the established financial calculation standards for the application.

## Artifact Traceability

### spec.md
- **Affected user story**: User Story 1 — Group Setup & Income Distribution, User Story 2 — Budgeting & Spending
- **Affected requirements**: 
    - **FR-018**: System MUST apply a consistent percentage rounding strategy (2 decimal places with Remainder Absorption by the highest earner) across all views.
- **Gap identified**: Implementation drift. The requirement is explicitly stated in the spec and was supposedly addressed in BUG-027, but the current behavior does not match the requirement.

### plan.md
- **Affected sections**: Backend/Logic, Technical Context
- **Impact**: The "Remainder Absorption" strategy implementation in `shared/logic/rounding.ts` and its application in serverless functions must be audited. The plan previously mandated this for Dashboard, Budget, and Savings views, but the integration appears incomplete or regressed.

### tasks.md
- **Affected tasks**: 
    - **T103**: Create a shared utility for percentage rounding and remainder absorption.
    - **T104**: Update DashboardSummary widget to use the shared rounding utility.
- **False completions**: T103 and T104 are marked complete but fail to satisfy the requirement globally.
- **Missing tasks**:
    - [ ] [US1] Audit `shared/logic/rounding.ts` for edge case handling (equal incomes, multiple members).
    - [ ] [US2] Update category share calculation logic in backend functions to use the shared rounding utility.
    - [ ] [US3] Verify savings goal contribution calculations apply remainder absorption.

## Root Cause Analysis
While BUG-027 introduced the rounding utility and updated the Dashboard, the core financial calculations for budget categories and savings goals likely still use raw division or inconsistent rounding methods. The shared utility may also lack robust tests for scenarios where the rounding difference needs to be absorbed by a specific member.
