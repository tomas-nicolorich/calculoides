# Bug Report: Silent Failure in Savings Goal Contribution Update

**Type**: Implementation drift
**Severity**: High
**Feature**: 001-calculoides-core-app
**Reported**: 2026-05-26
**Status**: Patched
**Patched**: 2026-05-26

## Description
When a user attempts to adjust a savings goal contribution amount in the UI, the application provides no feedback (error or success). However, the changed value is not reflected in the UI upon refresh and is not saved to the database. The system fails silently without triggering the expected recalculation or persistence logic.

## Artifact Traceability

### spec.md
- **Affected user story**: User Story 3 - Savings Goals & Proportional Contributions
- **Affected requirements**: 
    - **FR-006**: System MUST allow any group member to override their own or any other member's contribution and recalculate the projected date.
    - **SC-009**: Savings goal contribution overrides MUST validate that both the target goal and member exist.
- **Gap identified**: The specification lacks a requirement for explicit visual feedback (e.g., loading states, success/error toasts) during the contribution override process, contributing to the "silent" nature of the failure.

### plan.md
- **Affected sections**: Phase 5 (US3: Savings Goals)
- **Impact**: The "interactive savings goal contribution overrides" mandated by BUG-020 update is currently non-functional. The state transition and API integration logic in the frontend needs to be corrected to ensure terminal resolution and persistence.

### tasks.md
- **Affected tasks**: 
    - **T031**: Create Savings Goal CRUD and override endpoints in api/src/
    - **T032**: Implement Savings Goal widget in frontend/src/features/savings/
    - **T087**: Implement interactive contribution overrides in `SavingsGoalList` UI
- **False completions**: 
    - **T087**: Marked as complete, but the "interactive" part of the override is not persisting or reflecting changes.
- **Missing tasks**: 
    - Implement loading and error feedback for savings goal contribution updates.
    - Verify Zod schema coercion for contribution override payloads in the frontend client.

## Root Cause Analysis
Implementation drift. While the feature was marked as complete, the integration between the `SavingsGoalList` input fields and the `SavingsService.upsertContribution` endpoint is either missing a trigger (e.g., `onBlur` or `onClick` for save) or is failing to handle the asynchronous response from the API. The lack of error handling in the frontend masking a potential 4xx/5xx error or a silent failure in the service layer where the update is not reaching the `prisma.savingsGoalContribution.upsert()` call.
