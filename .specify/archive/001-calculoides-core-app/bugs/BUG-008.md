# Bug Report: Prisma Relation Naming Mismatch in Summary API

**Type**: Implementation drift
**Severity**: High
**Feature**: 001-calculoides-core-app
**Reported**: 2026-05-14

## Description
When calling the `/api/summary` endpoint, the system returns a 500 Internal Server Error. The console logs reveal a `PrismaClientValidationError` indicating that the `user` field is unknown for the `include` statement on the `group_members` model. The error suggests that the available option is `users` (plural).

```text
Invalid `prisma.groups.findUnique()` invocation in api:start:api:local: C:\Users\tnicolorich\Desktop\PROJECTS\calculoides\api\summary.ts:14:39
Unknown field `user` for include statement on model `group_members`. Available options are marked with ?.
? users?: true
```

## Root Cause Analysis
The `prisma/schema.prisma` file contains relation names that do not match the `data-model.md` specification. Specifically, the `group_members` model uses plural names (`users`, `groups`) for to-one relations, whereas the spec uses singular names (`user`, `group`). The code in `api/summary.ts` was implemented following the spec (`data-model.md`), leading to a validation error when interacting with the actual Prisma client generated from `schema.prisma`.

## Recommended Fix
1. Run `/speckit.bugfix.patch` to update `prisma/schema.prisma` to align with the singular naming convention defined in `data-model.md`.
2. Update `data-model.md` if any intentional changes were made to the schema that should be reflected in the spec.
3. Regenerate the Prisma client (`npx prisma generate`).
4. Run `/speckit.bugfix.verify` to confirm that the `/api/summary` endpoint now correctly includes the user data.
5. Resume `/speckit.implement` to ensure all other endpoints are consistent with the aligned schema.
