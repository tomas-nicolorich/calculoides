# Bug Report: BUG-038 - Lint errors due to `any` usage in API tests

**Type**: Implementation drift
**Severity**: High
**Feature**: 001-calculoides-core-app
**Reported**: 2026-06-05

## Description
The API test suite contains multiple linting errors caused by the use of the `any` type in mocks, assignments, and function parameters. This violates the project's strict TypeScript configuration and "type-safe stack" mandate. Specifically, `any` is used in `$transaction` mocks and when asserting result types in integration tests.

## Artifact Traceability

### spec.md
- **Affected requirements**: General architecture requirements for a "type-safe stack".
- **Gap identified**: While "strict mode" is mentioned in the plan, the spec does not explicitly mandate 0-lint-error status as a success criterion, which allowed these errors to accumulate.

### plan.md
- **Affected sections**: Technical Context
- **Impact**: The "TypeScript 6.0.3 (Strict Mode)" constraint is being violated in the test suite, preventing a clean lint/CI pass.

### tasks.md
- **Affected tasks**: T004 (Configure ESLint and Prettier for strict TypeScript 6.0.3)
- **False completions**: T004 is marked as complete, but the test files (T011, T012, T020, T021, T028, T033, T034, etc.) do not adhere to the strict configuration.
- **Missing tasks**: New tasks needed to:
  1. Define proper mock types for Prisma tx and services.
  2. Refactor all integration tests to eliminate `any` usage.

## Root Cause Analysis
During implementation of integration tests, `any` was used as a shortcut to bypass complex Prisma transaction types and service return types. This was likely done to speed up the TDD cycle, but it resulted in code that does not meet the project's quality standards for type safety.
