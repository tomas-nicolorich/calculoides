# Bug Report: Missing Auth Token in API Client

**Type**: Implementation drift
**Severity**: Critical
**Feature**: 001-calculoides-core-app
**Reported**: 2026-05-14

## Description
After a successful login, the application fails to fetch data from the backend (specifically `GET /api/groups`), resulting in a `401 Unauthorized` error. The browser console shows that the `client.ts` utility is throwing an "Unauthorized: Missing token" error. This indicates that the authentication state is not being correctly propagated from the `AuthProvider`/Supabase client to the API client for subsequent requests.

```text
GET http://localhost:5173/api/groups 401 (Unauthorized)
Failed to fetch groups Error: Unauthorized: Missing token
    at Object.fetch (client.ts:13:13)
    at async fetchGroups (DashboardPage.tsx:35:20)
```

## Artifact Traceability

### spec.md
- **Affected user story**: User Story 5 — Authentication & Navigation
- **Affected requirements**: 
    - **FR-010**: System MUST provide a user interface for authentication... integrated with the backend session service.
    - **FR-011**: System MUST maintain a consistent communication contract...
- **Gap identified**: While the spec mandates integration with the backend session service, it does not explicitly define the mechanism for token propagation from the frontend's Supabase client to the custom API client, leading to an implementation that fails to maintain the session across requests.

### plan.md
- **Affected sections**: Technical Context, Constraints
- **Impact**: The constraint "session-only auth (no localStorage)" is strictly enforced, but the plan lacks a specific strategy for the API client to access this in-memory or cookie-based session token. The plan needs to specify that the `client.ts` must be capable of retrieving the current session token from the Supabase client before making any authenticated request.

### tasks.md
- **Affected tasks**: 
    - **T049**: Create Auth feature (Login/Signup forms) in frontend/src/features/auth/
    - **T051**: Implement Auth guarded routes and integrate features into pages
    - **T053**: Verify Supabase client initialization in AuthProvider.tsx
- **False completions**: 
    - **T051**: This task was marked as complete, but the integration is broken as it doesn't handle the handover of the auth token to the API client.
- **Missing tasks**: 
    - Update `frontend/src/shared/api/client.ts` to dynamically retrieve and inject the Supabase session token into the `Authorization` header.
    - Add an integration test to verify that the `Authorization` header is present in outgoing requests after login.

## Root Cause Analysis
The project strictly prohibits `localStorage` for session storage (as per `plan.md`). Consequently, the API client (`client.ts`) cannot simply read a token from storage. It must instead interact with the Supabase client (which manages the session in memory/cookies) to obtain the JWT. The current implementation of `client.ts` either doesn't attempt this retrieval or the retrieval logic is failing, resulting in "Missing token".
