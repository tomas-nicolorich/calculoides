# Bug Report: Inconsistent Percentage Rounding in Overview

**Type**: Implementation drift
**Severity**: Medium
**Feature**: 001-calculoides-core-app
**Reported**: 2026-05-15

## Description
Percentages representing member income shares are properly rounded in the "Budget" section, but they appear with excessive decimal places or without proper rounding/remainder absorption in the "Overview" (Dashboard) section. This violates the general principle of consistent financial display and the specific rounding strategy defined in the research phase.

## Artifact Traceability

### spec.md
- **Affected user story**: User Story 1 — Group Setup & Income
- **Affected requirements**: Income share percentage calculation ("...A's share is 67% (66.67% rounded) and B's is 33% (33.33% rounded)").
- **Gap identified**: The spec defines the rounding strategy in "Edge Cases" (round to 2 decimal places with remainder absorption by the highest earner), but this is being applied inconsistently across different views.

### plan.md
- **Affected sections**: Backend/Logic (Vercel Serverless Functions for all financial computations to ensure accuracy and central control).
- **Impact**: The dashboard aggregation logic needs to be audited to ensure it utilizes the central rounding utility or that the frontend consistently applies the rounding strategy if performed client-side.

### tasks.md
- **Affected tasks**: 
    - **T026**: Implement Dashboard Summary widget in frontend/src/widgets/dashboard/
    - **T050**: Create Page components (Dashboard, Login, Settings) in frontend/src/pages/
- **False completions**: T050 is marked as complete but fails to satisfy the requirement for consistent rounding in the Dashboard view.
- **Missing tasks**: 
    - [ ] [US1] Create a shared utility for percentage rounding and remainder absorption.
    - [ ] [US1] Update `DashboardSummary` to use the shared rounding utility.

## Root Cause Analysis
The bug is likely due to the "Overview" section using a naive division for percentages without applying the "Remainder Absorption" logic defined in `research.md`. While the budget section was updated to handle this (possibly during BUG-019), the dashboard summary logic was overlooked.
