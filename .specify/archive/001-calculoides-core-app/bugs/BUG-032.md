# Bug Report: Delayed Savings Goal Contribution Updates

**Type**: Implementation drift
**Severity**: High
**Feature**: 001-calculoides-core-app
**Reported**: 2026-05-31
**Status**: Patched
**Patched**: 2026-05-31

## Description
When updating a saving goal contribution, the changes are not reflected in the UI immediately. The user is forced to perform a manual page reload to see the updated contribution and the recalculated projected completion date. This contradicts the requirement for instant feedback and terminal state resolution.

## Artifact Traceability

### spec.md
- **Affected user story**: User Story 3 — Savings Goals & Proportional Contributions
- **Affected requirements**: 
    - **FR-006**: "If contributions are overridden, the system MUST recalculate the projected date and display the variance from the original target date."
- **Gap identified**: While FR-006 mentions recalculation, it doesn't explicitly mandate *instant* UI reactivity, although **SC-011** (added in BUG-031) specifically mandates updates within 500ms without a reload.

### plan.md
- **Affected sections**: Technical Context, Technical Context (BUG-031)
- **Impact**: The plan specifically mandates "implementation of mandatory state synchronization and cache invalidation in savings goal contribution overrides" via the BUG-031 patch. The current behavior indicates this cache invalidation or state sync is missing or broken.

### tasks.md
- **Affected tasks**: 
    - **T110**: Implement UI state synchronization for savings goals in the contribution update mutation.
    - **T111**: Add an automated UI test to verify that savings goal projections update immediately after a contribution change without a reload.
- **False completions**: **T110** and **T111** are marked as complete `[x]`, but the user report confirms the behavior is not working as expected.
- **Missing tasks**: None. Existing tasks T110 and T111 need to be reopened and the automated test (T111) must be verified/fixed to catch this regression.

## Root Cause Analysis
Implementation drift. Although tasks T110 and T111 were marked as complete, the UI state synchronization (likely via React Query cache invalidation or local state update) is either not triggering correctly or the backend response is not being handled to update the frontend's view of the savings goal. This might be due to a race condition or a missing `await` in the mutation's `onSuccess` handler.
