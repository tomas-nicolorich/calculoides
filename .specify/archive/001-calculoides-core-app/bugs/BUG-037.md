# Bug Report: Missing `update` method in `apiClient.savings`

**Status**: Patched
**Patched**: 2026-06-04
**Type**: Implementation drift
**Severity**: High
**Feature**: 001-calculoides-core-app
**Reported**: 2026-06-04

## Description
When attempting to update an existing savings goal (changing name, target amount, starting amount, or target date), clicking the "Update Goal" button results in the error `apiClient.savings.update is not a function` being displayed below the form. No error is thrown in the browser console. This indicates that the UI is attempting to call a method that does not exist in the shared API client.

## Artifact Traceability

### spec.md
- **Affected user story**: User Story 3 — Savings Goals & Proportional Contributions
- **Affected requirements**: FR-006 (Savings goal calculation and management)
- **Gap identified**: While the spec mandates goal creation and contribution overrides, the capability to edit a goal's metadata (target amount, date, etc.) was implicitly introduced via BUG-033/036 (Starting Amount support) but the requirement for a corresponding update endpoint/client method was not explicitly documented as a standalone requirement.

### plan.md
- **Affected sections**: Technical Context (Frontend API client)
- **Impact**: The `apiClient` definition in `frontend/src/shared/api/client.ts` needs to be updated to include the `update` method mapping to the backend's `PATCH` handler.

### tasks.md
- **Affected tasks**: 
    - **T114**: "Update SavingsGoalForm and widget in frontend/src/features/savings/ to support startingAmount input and editing"
- **False completions**: **T114** is marked as complete, but the "editing" functionality is broken due to the missing client method.
- **Missing tasks**: 
    - Add `update` method to `apiClient.savings` in `frontend/src/shared/api/client.ts`.
    - Update `api/savings.ts` `Allow` header to correctly reflect `PATCH` support.

## Root Cause Analysis
This is a case of **Implementation drift**. During the implementation of `startingAmount` support (BUG-033/036), the backend was correctly updated to handle `PATCH` requests for goal updates, and the frontend UI was updated to provide an "editing" mode. However, the shared `apiClient`—which acts as the bridge between the two—was overlooked and never received the `update` method definition.

## Recommended Fix
1. Run `/speckit.bugfix.patch` to update spec artifacts (add missing tasks for client update and header synchronization).
2. Run `/speckit.bugfix.verify` to confirm consistency across the feature directory.
3. Resume `/speckit.implement` to apply the code fix:
    - Add `update: (goalId: string, data: { ... }) => apiClient.fetch(...)` to `frontend/src/shared/api/client.ts`.
    - Update `api/savings.ts` to include `PATCH` in the `Allow` header.
