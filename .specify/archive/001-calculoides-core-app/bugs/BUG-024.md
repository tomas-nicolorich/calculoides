# Bug Report: Persistent Null Constraint Violation in Expense Creation

**Type**: Implementation drift
**Severity**: Critical
**Status**: Patched
**Patched**: 2026-05-15
**Feature**: 001-calculoides-core-app
**Reported**: 2026-05-15

## Description
When creating an expense, the system throws a `PrismaClientKnownRequestError` with code `P2011` (Null constraint violation). The error trace points to `prisma.expense.create` in `api/src/services/expense.ts:45:33`.

```text
api:start:api:local: 43 finalPayerId = membership.id;
api:start:api:local: 44 api:start:api:local: 
→ 45 return await prisma.expense.create(
api:start:api:local: Null constraint violation on the (not available)
```

Investigation reveals that the `Expense` model in `prisma/schema.prisma` lacks a default value for the primary key `id`, which is a regression or incomplete fix for BUG-018. Additionally, several foreign key fields in the schema have been incorrectly assigned random UUID defaults.

## Root Cause Analysis
The primary cause of the `P2011` error is that `Expense.id` in `prisma/schema.prisma` is defined as `@id @db.Uuid` without `@default(dbgenerated("gen_random_uuid()"))`. Since `ExpenseService.logExpense` does not provide an ID, the database rejects the insert. 

Furthermore, the schema has "hallucinated" defaults for foreign keys (e.g., `categoryId`, `payerId`, `groupId` in various models), likely as a misguided attempt to resolve previous null constraint issues. These defaults generate random valid-looking but non-existent IDs, which would lead to foreign key violations (P2003) if the null constraints were bypassed.

## Recommended Fix
1. Run `/speckit.bugfix.patch` to update spec artifacts and reopen affected tasks.
2. Update `prisma/schema.prisma`:
    - Add `@default(dbgenerated("gen_random_uuid()"))` to `Expense.id`.
    - Remove `@default(dbgenerated("gen_random_uuid()"))` from all foreign key fields (including `categoryId`, `payerId`, `groupId`, `memberId`, etc. across all models).
3. Sync the database with the corrected schema.
4. Regenerate the Prisma client.
5. Resume `/speckit.implement` to verify the fix.
