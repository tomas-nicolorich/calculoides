# Bug Report: Missing starting amount and modification for savings goals

**Type**: Spec gap
**Severity**: Medium
**Feature**: 001-calculoides-core-app
**Reported**: 2024-05-15

**Status**: Patched
**Patched**: 2026-06-01

## Description
When creating a savings goal, the user should be able to input the starting amount (initial savings) and modify it afterwards. Currently, the system only supports a target amount and a target date, assuming a starting balance of zero. This prevents users from tracking goals where progress has already been made or manually adjusting the current balance.

## Artifact Traceability

### spec.md
- **Affected user story**: User Story 3 — Savings Goals & Proportional Contributions
- **Affected requirements**:
    - **Acceptance Scenario 1**: "Given a group, When a member creates a 'New Sofa' goal for €1200 with a 6-month deadline, Then the app should show each member's monthly contribution..."
    - **Glossary**: "Savings Goal: A target amount and date with calculated monthly contributions."
- **Gap identified**: The spec lacks a requirement for an initial balance (starting amount) and the ability to update that balance over time.

### plan.md
- **Affected sections**: Phase 5 (US3: Savings Goals)
- **Impact**: The plan needs to incorporate the addition of a `startingAmount` field to the database schema and update the calculation logic to `(Target - Starting) / Months`.

### tasks.md
- **Affected tasks**:
    - **T031**: Create Savings Goal CRUD and override endpoints in api/src/
    - **T032**: Implement Savings Goal widget in frontend/src/features/savings/
- **False completions**: None. The tasks were completed according to the original (incomplete) spec.
- **Missing tasks**:
    - Update `SavingsGoal` Prisma model to include `startingAmount`.
    - Update `SavingsService` calculation logic to account for `startingAmount`.
    - Update `SavingsGoalForm` and widget to support starting amount input and editing.

## Root Cause Analysis
Spec oversight. The initial design of the Savings Goal feature assumed all goals start from zero, which does not cover common use cases where users have existing savings or need to manually record progress.
