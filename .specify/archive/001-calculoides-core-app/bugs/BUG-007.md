# Bug Report: Dashboard Persistent Loading Spinner After Login

**Type**: Untested flow
**Severity**: High
**Feature**: 001-calculoides-core-app
**Reported**: 2026-05-14
**Status**: Patched
**Patched**: 2026-05-14

## Description
After a successful login, the user is redirected to the `/dashboard` route. However, the page displays a persistent loading spinner that never disappears. No errors are reported in the browser console, and there are no failed network requests. The application appears to be stuck in an initialized "loading" state, preventing users from accessing their financial data.

## Root Cause Analysis
The issue is likely a race condition in the `AuthProvider`. Because the project uses "session-only auth" (no localStorage), it depends entirely on the Supabase client's initial session retrieval and the `onAuthStateChange` listener. If the dashboard component mounts before the session is confirmed, it shows a spinner. If the confirmation (or rejection) never reaches the component (e.g., due to an unhandled promise or a listener that doesn't fire for already-cached-but-unverified sessions), the spinner persists indefinitely without producing a console error.
