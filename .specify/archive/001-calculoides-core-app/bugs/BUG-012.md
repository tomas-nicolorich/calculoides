# Bug Report: Expense Logging Date Validation Failure

**Type**: Untested flow
**Severity**: High
**Feature**: 001-calculoides-core-app
**Reported**: 2026-05-15

## Description
When attempting to log an expense, the API returns a Zod validation error: `Invalid input: expected date, received string`. This occurs because the `CreateExpenseSchema` uses `z.date()` for the `date` field, which fails when receiving an ISO date string from a JSON request body.

### spec.md

## Root Cause Analysis
The `ExpenseSchema` in `shared/validation.ts` uses `z.date()`, which strictly requires a JavaScript `Date` object. Since the frontend sends data as JSON, the `date` field arrives at the backend as a string. Express does not automatically convert these strings to Date objects, leading to a type mismatch in Zod validation.
