## Root Cause Analysis
The error `P2011` confirms that a required field is null. In `ExpenseService.logExpense`, the `create` call passes `categoryId`, `payerId`, `description`, `amount`, and `date`. 
1. **ID Type Mismatch**: The database migration (`0_init`) uses `TEXT` for IDs, but the `schema.prisma` uses `@db.Uuid`. This discrepancy can cause issues with the `pg-adapter`.
2. **Missing Field**: If `isArchived` or another field marked as `NOT NULL` in the DB doesn't have a functioning default at the database level, and Prisma doesn't provide it, the insert fails.
3. **Null Resolution**: If `membership.id` is somehow null (though unlikely given the check), it would trigger this.
4. **Amount Coercion**: `amount` is a `number` in JS but `DECIMAL` in PG.

## Recommended Fix
1. Run `/speckit.bugfix.patch` to update spec artifacts and tasks.
2. Align `schema.prisma` with `0_init` migration or vice versa (preferring UUIDs if supported by the environment).
3. Add explicit validation/defaults for all `NOT NULL` fields in the service layer.
4. Resume `/speckit.implement` to apply the code fix.
