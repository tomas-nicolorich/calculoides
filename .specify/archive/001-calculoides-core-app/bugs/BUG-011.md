# Bug Report: Group Member Visibility & Admin Access (BUG-011)

**Status**: Patched
**Patched**: 2026-05-14
**Type**: Implementation drift
**Severity**: High
**Feature**: 001-calculoides-core-app
**Reported**: 2026-05-14

## Description
Inside a group, the Members tab fails to display any group members, even when they exist. Additionally, the group owner is unable to access the Admin tab, receiving an "access denied" or similar blocking behavior despite having the required ownership privileges.

## Artifact Traceability

### spec.md
- **Affected user story**: 
  - US1 — Group Setup & Income Distribution (Member visibility)
  - US4 — Budget Transfers & Archiving (Owner-only management)
- **Affected requirements**: 
  - FR-004 (Dashboard MUST show recent expenses, transfers, and category status... implying member visibility)
  - FR-008 (Owners have exclusive permissions to invite/remove members, transfer budgets for all members, and archive expenses)
- **Gap identified**: Implementation fails to correctly identify the owner in the frontend and/or fails to retrieve/display group members due to restrictive RLS policies or incomplete data hydration.

### plan.md
- **Affected sections**: Technical Context (Supabase RLS, Auth initialization), Project Structure (frontend features)
- **Impact**: RLS policies for the `group_members` table must be audited to ensure visibility for all group members. The frontend ownership check logic (`member.isOwner` or `group.ownerId`) needs to be verified and synchronized with the API response.

### tasks.md
- **Affected tasks**: 
  - T007: Implement Supabase RLS base policies for multi-tenancy
  - T019: Implement Group Member list and Invitation UI
  - T040: Add Archive management for Owners in frontend/src/features/admin/
- **False completions**: 
  - T007 (RLS policies are likely blocking member visibility)
  - T019 (Member list is empty/broken)
  - T040 (Admin UI is inaccessible to valid owners)
- **Missing tasks**:
  - Audit and fix RLS policies for `group_members` table to allow group-wide visibility.
  - Verify `Group` object hydration in the frontend to include `ownerId` and `members`.

## Root Cause Analysis
Preliminary analysis suggests two likely causes:
1. **RLS Policy Restriction**: The `group_members` table RLS policies might be set to `auth.uid() = user_id`, which prevents users from seeing other members in the same group. Policies should allow visibility if `auth.uid()` belongs to any `group_member` of the same `group_id`.
2. **Frontend Ownership Check**: The Admin tab access check might be relying on a stale or incomplete `Group` object where the `ownerId` is missing or the current user's role isn't correctly identified during navigation.
