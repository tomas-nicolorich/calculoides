# Bug Report: Missing Initial Amount and Null Projections on /savings

**Type**: Implementation drift
**Severity**: High
**Feature**: 001-calculoides-core-app
**Status**: Patched
**Patched**: 2026-06-03

## Description
The `/savings` endpoint is returning `null` for `projectedDate` and `varianceMonths` instead of calculated values. Additionally, the `initialAmount` (mapped from `startingAmount` in the database) is completely missing from the API response when its value is `0`, even though it is correctly stored in the database. This prevents the frontend from correctly displaying the goal progress and projected completion.

## Artifact Traceability

### spec.md
- **Affected user story**: User Story 3 — Savings Goals & Proportional Contributions
- **Affected requirements**: 
  - **FR-006**: "If contributions are overridden, the system MUST recalculate the projected date and display the variance from the original target date."
  - **SC-012**: "Savings goals MUST support an optional `startingAmount` (default 0) that is subtracted from the `targetAmount` before calculating monthly contributions."
- **Gap identified**: None. The spec explicitly requires these values to be handled and calculated.

### plan.md
- **Affected sections**: Backend/Logic (savings projections), Technical Context (Savings goal contribution overrides).
- **Impact**: The calculation logic in `SavingsService` is likely failing (returning `null`) or not being triggered correctly. The serialization logic for the `/savings` response is omitting the `startingAmount` when it is `0`.

### tasks.md
- **Affected tasks**: 
  - **T030**: Implement SavingsService with dynamic deadline logic (reopened)
  - **T031**: Create Savings Goal CRUD and override endpoints (reopened)
  - **T113**: Update SavingsService calculation logic to subtract startingAmount
  - **T114**: Update SavingsGoalForm and widget to support startingAmount
- **False completions**: 
  - **T113**, **T114** (The logic for `startingAmount` appears to be incomplete or broken for the `0` value case)
  - **T030** (Projected date calculation is returning `null`)
- **Missing tasks**: 
  - Add regression test for `startingAmount = 0` serialization.
  - Add regression test for `null` projected date results in `SavingsService`.

## Root Cause Analysis
1. **Null Projections**: Likely caused by a failure in `SavingsService.calculateProjectedDate` or similar logic where a division by zero or an invalid date math operation results in `null` (perhaps as a "safe" but incorrect fallback from BUG-035 fix).
2. **Missing Initial Amount**: Likely a serialization issue in the API layer (e.g., `savings.ts` route or `SavingsService` DTO mapping) where a falsy check `if (goal.startingAmount)` is used, causing `0` to be treated as "not present" and omitted from the response.
