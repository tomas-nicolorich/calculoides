# Bug Report: Incorrect Share Calculation for Category Subsets

**Status**: Patched
**Patched**: 2026-05-28
**Type**: Implementation Drift
**Severity**: High
**Feature**: 001-calculoides-core-app
**Reported**: 2026-05-28

## Description
Shares are not calculated correctly when a budget category has a subset of members. Instead of recalculating percentages based on the combined income of only the subset members (as mandated by the spec), the system is currently using the group-wide income shares and simply filtering for the subset members. This results in category shares that do not sum to 100% and incorrect individual quotas.

## Artifact Traceability

### spec.md
- **Affected user story**: User Story 2 — Budgeting & Spending
- **Affected requirements**: 
    - **FR-002**: "System MUST calculate income percentage shares based on the total combined income of all members (or selected subset) in a group."
    - **User Story 2 Acceptance Scenario 3**: "Given a category with a restricted subset of members, When income percentages are calculated, Then only the income of those selected members should be used to determine the shares."
- **Gap identified**: None. The specification is correct and explicit about this requirement.

### plan.md
- **Affected sections**: Technical Context, BUG-017, BUG-028.
- **Impact**: The plan mandates handling many-to-many relationship management for optional member subsets (BUG-017) and consistent financial logic (BUG-028), but the implementation strategy in `api/src/services/budget.ts` failed to incorporate the per-category recalculation requirement.

### tasks.md
- **Affected tasks**: 
    - **T085**: "Update `BudgetService` to return per-member spending and quota breakdown for each category (BUG-019)"
    - **T106**: "Update category share calculation logic in backend functions to use the shared rounding utility (BUG-028)"
- **False completions**: 
    - **T085**: Marked as complete, but the returned breakdown is mathematically incorrect for subset categories.
- **Missing tasks**: 
    - Refactor `BudgetService.listCategoriesWithBalances` to trigger `calculateIncomeShares` per category if a `memberLinks` subset is present.

## Root Cause Analysis
The `BudgetService.listCategoriesWithBalances` method fetches all group members and calculates a single set of `incomeShares` based on the total group income. For categories with a restricted subset of members, it filters these global shares instead of passing the subset of members to the calculation service to derive new proportional percentages.
