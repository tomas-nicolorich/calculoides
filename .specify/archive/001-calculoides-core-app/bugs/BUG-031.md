# Bug Report: Stale UI State after Savings Goal Contribution Update

**Type**: Untested flow
**Severity**: Medium
**Feature**: 001-calculoides-core-app
**Reported**: 2026-05-30
**Status**: Patched
**Patched**: 2026-05-30

## Description
When a user updates a savings goal contribution amount, the change is correctly persisted to the database. However, the UI (specifically the `SavingsGoalList` component and the projected completion dates) does not update to reflect the new values or calculations until the page is manually reloaded. The application should instantly reflect these changes to provide a responsive user experience.

## Artifact Traceability

### spec.md
- **Affected user story**: User Story 3 — Savings Goals & Proportional Contributions
- **Affected requirements**: 
    - **FR-006**: "Any group member MUST be able to override their own or any other member's contribution. If contributions are overridden, the system MUST recalculate the projected date and display the variance from the original target date."
    - **SC-002**: "Proportional shares are recalculated and updated on the dashboard within 500ms of an income or category change." (Implicitly applies to savings goals, but lacks explicit mandate for overrides).
- **Gap identified**: Success criteria **SC-002** explicitly mentions income and category changes but omits savings goal contribution overrides. This led to an implementation that persists data but fails to synchronize the frontend state.

### plan.md
- **Affected sections**: Phase 5 (US3: Savings Goals)
- **Impact**: The "interactive" mandate from [BUG-020] and "terminal resolution" from [BUG-026] must be extended to include mandatory state synchronization/cache invalidation.

### tasks.md
- **Affected tasks**: 
    - **T032**: Implement Savings Goal widget in frontend/src/features/savings/
    - **T087**: Implement interactive contribution overrides in `SavingsGoalList` UI
- **False completions**: **T087** is marked as complete, but the "interactive" aspect is fundamentally broken if the UI remains stale after an update.
- **Missing tasks**: 
    - Implement React Query cache invalidation (or equivalent state refresh) in the contribution update mutation hook.
    - Add an automated UI test to verify that projections update immediately after a contribution change without a reload.

## Root Cause Analysis
The root cause is an "Untested flow" in the frontend implementation. While the API integration (T031) and the basic UI input (T087) were implemented and verified for data persistence, the "loop" was never closed with a cache invalidation or local state update. The TDD approach likely focused on the API response rather than the subsequent UI reaction.
