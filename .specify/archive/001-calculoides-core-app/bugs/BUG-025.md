# Bug Report: Missing Expense Visibility

**Type**: Spec gap
**Severity**: High
**Feature**: 001-calculoides-core-app
**Reported**: 2026-05-15
**Status**: Patched
**Patched**: 2026-05-25

## Description
Users can successfully log expenses, and the system correctly updates the category balances and personal quotas. However, there is no UI component available for users to view the list of individual expenses that have been created. While the "Summary" exists, the "History" or "List" is absent, making it impossible to verify, audit, or identify specific transactions.

## Artifact Traceability

### spec.md
- **Affected user story**: User Story 2 — Budgeting & Spending
- **Affected requirements**: FR-004 (Dashboard visibility), User Story 2 Acceptance Scenarios.
- **Gap identified**: FR-004 mandates that the dashboard show "recent expenses", but the spec lacks a requirement for a comprehensive expense history or a way to view all expenses associated with a specific category. This ambiguity led to an implementation that tracks data internally but fails to expose it to the user.

### plan.md
- **Affected sections**: Frontend Implementation (US2), Dashboard Widget Strategy.
- **Impact**: The plan must be updated to include an `ExpenseList` feature slice or widget to provide visibility into the `Expense` entity records.

### tasks.md
- **Affected tasks**: 
    - `T026`: Implement Dashboard Summary widget
    - `T027`: Create Category list and Expense entry UI
- **False completions**: `T026` and `T027` are marked complete but have failed to satisfy the visibility requirement of FR-004.
- **Missing tasks**:
    - `T098 [US2] Implement CategoryExpenseList component to show entries for a specific category`
    - `T099 [US2] Update Dashboard widget to include a 'Recent Expenses' feed as per FR-004`
    - `T100 [US2] Create API endpoint GET /api/expenses to fetch paginated/filtered expense history`

## Root Cause Analysis
Spec oversight/ambiguity. The specification focused heavily on the calculation logic and the "logging" action but did not explicitly detail the "viewing" requirements for active (non-archived) expenses. This resulted in the implementation of the data model and calculation services without the corresponding UI for data retrieval and display.

## Recommended Fix
1. Run `/speckit.bugfix.patch` to update spec artifacts (specifically FR-004 and US2 scenarios) to mandate a visible expense list.
2. Run `/speckit.bugfix.verify` to confirm consistency across artifacts.
3. Resume `/speckit.implement` to implement the missing `ExpenseList` UI and supporting API endpoint.
