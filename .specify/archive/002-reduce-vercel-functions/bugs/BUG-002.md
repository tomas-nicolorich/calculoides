# Bug Report: Build failure due to DB connection requirement in SSG script

**Type**: Dependency issue
**Severity**: High
**Feature**: 002-reduce-vercel-functions
**Reported**: 2024-05-22
**Status**: Fixed

## Description
The `npm run build` command failed during the `prebuild` phase of the `frontend` package. The `prebuild` hook executes `npm run api:generate-categories`, which attempts to fetch category data from the database using Prisma. If the database is unreachable, the script throws `ECONNREFUSED`, causing the entire build to fail.

## Artifact Traceability

### spec.md
- **Affected user story**: User Story 2 - Remove or Migrate Redundant Functions
- **Affected requirements**: SC-003 (Build and deployment to Vercel succeeds)
- **Gap identified**: The specification assumes database availability during the build process but does not define behavior for when it is unavailable.

### plan.md
- **Affected sections**: Phase 4: User Story 2 - Redundant Removal
- **Impact**: T015 and T016 introduced a build-time dependency on an external resource (Database) without a fallback mechanism.

### tasks.md
- **Affected tasks**: T016 [US2] Update `frontend/package.json` build step to run Categories SSG script.
- **False completions**: T016 was marked complete but caused regressions in disconnected environments.

## Root Cause Analysis
The `generate-categories.ts` script lacked robustness against connection failures. While SSG ideally fetches fresh data at build time, hard-failing the build when the database is unreachable prevents developers from building the application locally or in restricted environments.

## Resolution
Modified `api/scripts/generate-categories.ts` to gracefully handle Prisma connection errors. The script now:
1. Logs a warning and the error message if the database is unreachable.
2. Continues the build with an empty array or the existing `categories.json` file.
3. Only overwrites the output file if new data is successfully fetched or if the file does not yet exist.
This ensures that `npm run build` succeeds even in offline environments while still supporting SSG when connectivity is available.
