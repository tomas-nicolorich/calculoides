# Bug Report: 404 Error on api/invitations in Local Development

**Status**: Patched
**Patched**: 2026-05-21
**Type**: Implementation drift
**Severity**: High
**Feature**: 002-reduce-vercel-functions
**Reported**: 2026-05-21

## Description
Requests to `/api/invitations` return a 404 error when running the server locally via `npm run dev`. This occurs because the original `api/invitations.ts` handler was removed during consolidation (T017), and the local Express server (`api/src/server.ts`) only implements file-system based routing. It does not respect the routing rewrites defined in `vercel.json`, which are required to map the legacy logical paths to the new consolidated handlers.

## Artifact Traceability

### spec.md
- **Affected user story**: US1 — Consolidate Related Functions
- **Affected requirements**: 
    - **FR-004**: All public-facing API endpoints MUST maintain their original behavior and response format.
    - **FR-005**: Infrastructure-as-Code (vercel.json) MUST be used to explicitly manage function grouping and route mapping.
- **Gap identified**: While the spec mandates using `vercel.json` for mapping, it did not explicitly specify that the local development environment must achieve parity with Vercel's rewrite engine to satisfy FR-004.

### plan.md
- **Affected sections**: Phase 2: Foundational Infrastructure, Phase 6: Verification & Polish.
- **Impact**: The local server implementation (Phase 2) is incomplete as it lacks rewrite support. Verification (Phase 6) passed despite this regression.

### tasks.md
- **Affected tasks**: 
    - **T005**: Update `api/src/server.ts` to recursively load routes. (Incomplete: should also load rewrites).
    - **T024**: Manual end-to-end verification of all endpoints via `npm run dev`. (False completion).
- **False completions**: T024 is marked as complete, but a manual check of all endpoints would have revealed 404s for all consolidated routes.
- **Missing tasks**: 
    - New Task: Update `api/src/server.ts` to parse `vercel.json` and apply rewrites to the Express application.

## Root Cause Analysis
Implementation drift between the Vercel deployment configuration and the local development server. The project moved from 1:1 file-to-route mapping to a consolidated many-to-one mapping managed by `vercel.json`. The local server was updated to load the new handlers but was not updated to simulate the rewrite layer that maps the old logical paths to these handlers.

## Recommended Fix
1. Run `/speckit.bugfix.patch` to update `tasks.md` (reopen T024, add new rewrite task) and `plan.md`.
2. Modify `api/src/server.ts` to:
    - Load `vercel.json`.
    - Implement a rewrite middleware or iterate through the `rewrites` array to create Express routes that proxy/forward to the consolidated handlers.
3. Resume implementation and verify all endpoints listed in `research.md` return 200/Expected results locally.
