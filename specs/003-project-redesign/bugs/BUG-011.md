# Bug Report: Cannot Find Module '.prisma/client/default' on Vercel

**Status**: Patched
**Patched**: 2026-05-29
**Type**: Dependency issue
**Severity**: Critical
**Feature**: 003-project-redesign
**Reported**: 2026-05-29

## Description
Once deployed to Vercel and logged in, the application is unable to fetch groups or perform any database operations. Any API requests that query the database (such as `GET /api/groups`) result in an HTTP 500 Internal Server Error. The Vercel runtime logs reveal the following error trace:

```text
Cannot find module '.prisma/client/default' Require stack:
- /var/task/node_modules/\@prisma/client/default.js
- /var/task/api/src/utils/prisma.js
- /var/task/api/src/services/group.js
- /var/task/api/src/handlers/groups.js
- /var/task/api/groups.js
Did you forget to add it to "dependencies" in `package.json`?
Node.js process exited with exit status: 1.
```

This error prevents any database communication, rendering the deployed application completely non-functional.

## Root Cause Analysis
Prisma Client is a generated library. During local development, the client is compiled into the `node_modules` directory whenever `npx prisma generate` is executed. However, when deploying to Vercel, the platform installs dependencies but does not automatically compile the Prisma Client unless an explicit generate step is declared.

Because the Prisma schema is located at `prisma/schema.prisma` in the root workspace, and the `prisma` dependency is scoped inside the `api` workspace, Vercel's deployment builder has no automatic trigger to compile the client. As a result, the serverless functions cannot find the `.prisma/client` folder or `.prisma/client/default` module at runtime, leading to a module loading crash.
