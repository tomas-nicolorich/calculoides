# Bug Report: Category Deletion Misrouted to Expense Deletion

**Type**: Implementation drift
**Severity**: High
**Feature**: 003-project-redesign
**Reported**: 2026-05-31
**Status**: Patched
**Patched**: 2026-05-31

## Description
When attempting to delete a budget category, the system returns a `ZodError: Invalid UUID`. This occurs because the frontend request to `/api/transactions/category-delete?id=[UUID]` is being captured by a greedy rewrite rule in `vercel.json` and misrouted to the `expense-delete` handler with the literal string `"category-delete"` as the `id`.

## Root Cause Analysis
The `vercel.json` contains the following rewrite rule:
```json
{
  "source": "/api/transactions/:id",
  "destination": "/api/transactions?action=expense-delete&id=:id",
  "methods": ["DELETE"]
}
```
The frontend in `DashboardPage.tsx` calls:
`await apiClient.fetch("/api/transactions/category-delete?id=${id}", { method: 'DELETE' });`

Because `:id` matches `"category-delete"`, the dispatcher receives `action=expense-delete` and `id="category-delete"`. The `expense-delete` handler then fails to parse `"category-delete"` as a UUID via `IdSchema.parse(id)`.

## Recommended Fix
1. Run `/speckit.bugfix.patch` to update `plan.md` and `tasks.md` to include category-specific logical path mapping.
2. Update `vercel.json` to add a specific rewrite for category deletion *before* the greedy transaction deletion rule:
   ```json
   {
     "source": "/api/categories/:id",
     "destination": "/api/transactions?action=category-delete&id=:id",
     "methods": ["DELETE"]
   }
   ```
3. Update `DashboardPage.tsx` to use the new logical path: `/api/categories/${id}`.
4. Run `/speckit.bugfix.verify` to confirm consistency.
5. Resume `/speckit.implement` to apply the code fix.
