# Bug Report: Default Browser Alert Usage

**Type**: Implementation drift
**Severity**: Medium
**Feature**: 003-project-redesign
**Reported**: 2026-06-01
**Status**: Patched
**Patched**: 2026-06-01

## Description
The application is currently using the browser's default `alert()` or `confirm()` pop-ups for user feedback and actions (e.g., confirming category deletion). This diverges from the project's goal of a "sleek, colorful, and subtle" custom design and breaks the visual immersion of the redesign.

## Artifact Traceability

### spec.md
- **Affected user story**: Global Design Pattern
- **Affected requirements**: SC-003
- **Gap identified**: While SC-003 mandates a "sleek, colorful, and subtle" card-based design for 100% of the UI, it does not explicitly define the replacement of standard browser dialogs with custom UI components, leading to implementation using `window.alert`.

### plan.md
- **Affected sections**: Summary, Technical Context
- **Impact**: The plan mentions using `@base-ui-components/react` and Tailwind CSS 4 for the aesthetic, but lacks a specific directive for a global custom alert/dialog system.

### tasks.md
- **Affected tasks**: T013c (Owner-only "Delete Category" logic with confirmation), T028 (Integrate Sign Out)
- **False completions**: T013c is marked complete but uses a browser `confirm()` which doesn't meet the aesthetic requirement of the redesign.
- **Missing tasks**: 
    - [ ] T039 [US1] Create a custom Alert/Dialog primitive using Base UI in `frontend/src/shared/ui/Dialog.tsx`
    - [ ] T040 [US1] Replace browser `confirm()` in `frontend/src/widgets/dashboard/ui/BudgetCategories.tsx` with the new custom Dialog component.

## Root Cause Analysis
The specification (SC-003) was broad enough to imply custom dialogs but didn't explicitly forbid browser defaults. Implementation followed the path of least resistance for confirmation logic (using `window.confirm`) during task T013c.

## Recommended Fix
1. Run `/speckit.bugfix.patch` to update spec artifacts to explicitly require custom dialogs.
2. Run `/speckit.bugfix.verify` to confirm consistency.
3. Resume `/speckit.implement` to apply the code fix and replace browser alerts with Base UI Dialogs.
