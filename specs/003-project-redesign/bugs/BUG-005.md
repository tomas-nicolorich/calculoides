# Bug Report: 404 Error on Expense Deletion

**Type**: Implementation drift
**Severity**: High
**Feature**: 003-project-redesign
**Reported**: 2026-05-30

## Description
When attempting to delete an expense, the application makes a GET request to `http://localhost:5173/api/transactions/category-delete?id=...` which returns a 404 Not Found error. 

Key issues:
1. The endpoint name `category-delete` is used for deleting an individual expense (transaction).
2. The request uses `GET` with a query parameter instead of `DELETE`.
3. The path does not match the logical API paths defined in the spec assumptions.

## Artifact Traceability

### spec.md
- **Affected user story**: User Story 2 — Expense Management
- **Affected requirements**: FR-016 (Delete actions), though FR-016 specifically mentions "Delete actions for each category", the general "Expense Management" flow (US2) is where this failure occurs.
- **Gap identified**: The spec (and assumptions) clarifies that the frontend MUST use logical API paths (rewrites) like `/api/summary` or `/api/categories`. However, it does not explicitly define the logical path for *deleting* a transaction/expense. The implementation is currently using a non-standard or missing logical path.

### plan.md
- **Affected sections**: Technical Context (Constraints), Project Structure (API).
- **Impact**: The API routing assumption (BUG-002) needs to be enforced for transaction deletion. The frontend implementation of the delete action needs to be corrected to use the proper logical path and HTTP method.

### tasks.md
- **Affected tasks**: 
    - T013c: Implement Owner-only "Delete Category" logic (if this was mistakenly used for expenses).
    - T018: Implement Recent Expenses card (where the delete action likely originates).
- **False completions**: T018 (if the delete action was part of its implementation).
- **Missing tasks**: A new task is needed to define and implement the correct logical API path for transaction deletion in both the frontend and backend (via `vercel.json` rewrites).

## Root Cause Analysis
Implementation drift. The frontend code is attempting to call an endpoint (`/api/transactions/category-delete`) that either does not exist, is misnamed, or is being called with the wrong HTTP method (GET instead of DELETE). Furthermore, this path violates the project convention of using logical "clean" paths (e.g., `/api/transactions/<id>`).

## Recommended Fix
1. Run `/speckit.bugfix.patch` to update `spec.md` and `plan.md` to explicitly define the logical path for transaction deletion (e.g., `DELETE /api/transactions/:id`).
2. Run `/speckit.bugfix.verify` to confirm consistency across artifacts.
3. Resume `/speckit.implement` to:
    - Update `vercel.json` to include the rewrite for the deletion endpoint.
    - Correct the frontend call in the Expenses widget to use the `DELETE` method and the correct logical path.
