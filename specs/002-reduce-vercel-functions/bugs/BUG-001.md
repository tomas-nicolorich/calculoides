# Bug Report: Widespread lint errors in api and frontend packages

**Type**: Implementation drift
**Severity**: High
**Feature**: 002-reduce-vercel-functions
**Reported**: 2024-05-22
**Status**: Fixed

## Description
Running `npm run lint` fails with over 80 problems across the project. 
- `frontend`: 4 errors in `client.test.ts` (Fixed).
- `api`: 83 errors across scripts, handlers, and tests (Fixed).
The `api/tsconfig.json` was misconfigured, excluding the `scripts/` directory, which hid several errors. Many tests used `any` to mock Request/Response objects, violating `@typescript-eslint` rules.

## Root Cause Analysis
1. Premature marking of quality tasks as complete.
2. Misconfigured `tsconfig.json` masking errors in scripts.
3. Over-reliance on `any` in test suites instead of using proper mock types or interfaces.

## Resolution
1. Updated `api/tsconfig.json` to include the `scripts/` directory.
2. Systematic cleanup of all `@typescript-eslint` violations in `api` source and scripts.
3. Refactored all API tests to use `Request`, `Response`, `ApiRequest`, `ApiResponse`, and `RouteConfig` types, removing unsafe `any` casts.
4. Fixed type errors in `frontend/src/shared/api/client.test.ts` by removing invalid `user` property from mock session data.
5. Verified with `npm run lint` and `tsc --noEmit` across all packages.
