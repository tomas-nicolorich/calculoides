# Bug Report: Savings goal created in DB but not visible in UI

**Status**: Patched
**Patched**: 2026-05-14
**Type**: Untested flow
**Severity**: High
**Feature**: 001-calculoides-core-app
**Reported**: 2026-05-14

## Description
When creating a new saving goal, the operation succeeds (verified by checking the database), and no errors are displayed to the user. However, the newly created saving goal does not appear in the "Savings" tab/widget. This suggests a failure in the UI refresh logic, a filtering issue in the frontend fetch, or a database-level access restriction (RLS) preventing the reading of the newly created record.

## Root Cause Analysis
Possible root causes:
1. **RLS Policy**: The Supabase RLS policy for `savings_goals` might allow `INSERT` but have an overly restrictive or missing `SELECT` policy.
2. **Cache/State Sync**: The frontend might not be refetching the savings goals list after a successful creation.
3. **Frontend Filtering**: The query used to fetch savings goals might be filtering by a parameter (e.g., `groupId`) that is incorrectly handled or missing in the creation/fetch handshake.
