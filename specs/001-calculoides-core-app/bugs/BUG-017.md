# Bug Report: Missing Category Member Selection

**Type**: Spec gap
**Severity**: Medium
**Feature**: 001-calculoides-core-app
**Status**: Patched
**Patched**: 2026-05-15
**Reported**: 2026-05-15

## Description
The user reported that when creating a budget category, there is no option to select the "optional subset of members" as specified in the requirements. This prevents the system from calculating shares based on a restricted group of members, which is a core part of the budgeting logic for specific shared expenses (e.g., a category shared by only two out of three housemates).

## Artifact Traceability

### spec.md
- **Affected user story**: User Story 2 — Budgeting & Spending
- **Affected requirements**: Budget categories description ("...and an optional subset of members") and Acceptance Scenario 3 ("Given a category with a restricted subset of members...").
- **Gap identified**: The spec defines the requirement, but the Phase 4 tasks in `tasks.md` and the implementation plan in `plan.md` do not explicitly mandate the UI or API support for this selection.

### plan.md
- **Affected sections**: Technical Context / Scale/Scope
- **Impact**: The plan needs to explicitly include the many-to-many relationship management in the Category management flow (Frontend FSD and Backend Services).

### tasks.md
- **Affected tasks**: 
    - T025: Create Category management and Expense logging endpoints in api/src/
    - T027: Create Category list and Expense entry UI in frontend/src/features/budget/
- **False completions**: None (tasks are already reopened for other bugfixes).
- **Missing tasks**: 
    - [ ] [US2] Implement member selection component in the Category creation form (Frontend).
    - [ ] [US2] Update `BudgetService.createCategory` to handle nested `memberLinks` (Backend).

## Root Cause Analysis
This is a spec gap in the implementation breakdown. While the high-level requirement and data model exist, the specific tasks for "Category management" (T025, T027) were interpreted too narrowly, focusing on the basic Category entity without implementing the join logic for `CategoryMember`.

## Recommended Fix
1. Run `/speckit.bugfix.patch` to update `tasks.md` and `plan.md` with explicit requirements for Category member selection.
2. Run `/speckit.bugfix.verify` to confirm consistency.
3. Resume `/speckit.implement` to apply the UI and API changes.
