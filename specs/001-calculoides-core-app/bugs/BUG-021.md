# Bug Report: Invitation Email Not Sent

**Type**: Implementation drift
**Severity**: High
**Feature**: 001-calculoides-core-app
**Reported**: 2026-05-15

**Status**: Patched
**Patched**: 2026-05-15

## Description
When a group owner invites a user via email, the `Invitation` record is successfully created in the database, but no email is dispatched to the recipient. Consequently, invited users do not receive the necessary join link to participate in the group.

## Artifact Traceability

### spec.md
- **Affected user story**: User Story 1 - Group Setup & Income Distribution
- **Affected requirements**:
    - **Acceptance Scenario 2**: "Given a group owner, When they invite a user via email, Then the invited user should receive an invitation and be able to join the group."
    - **Assumptions**: "Invite Logic: Invitations are sent via email, and the system handles the delivery and acceptance flow."
- **Gap identified**: The specification assumes email delivery but doesn't specify the email provider or the structure of the "join link".

### plan.md
- **Affected sections**: Technical Context, Project Structure.
- **Impact**: The plan lacks an email service integration (e.g., Resend, SendGrid) and a strategy for generating secure invitation links.

### tasks.md
- **Affected tasks**: 
    - `T016 [US1] Create InvitationService with email logic in api/src/services/invitation.ts`
- **False completions**: `T016` is marked as complete, but `InvitationService.ts` contains no email dispatch logic.
- **Missing tasks**: 
    - Integrate an email provider (e.g., Resend).
    - Implement email template for invitations.
    - Generate secure tokens/links for joining groups.

## Root Cause Analysis
Implementation drift: Task `T016` was marked as complete even though the `InvitationService` only implements the database persistence layer and lacks the email dispatch logic required by the specification. Additionally, the project lacks an email provider configuration.

## Recommended Fix
1. Run `/speckit.bugfix.patch` to update `spec.md` with email provider details and `plan.md` with integration strategy.
2. Run `/speckit.bugfix.verify` to confirm consistency.
3. Resume `/speckit.implement` to:
    - Add an email provider (e.g., `resend`) to the API.
    - Update `InvitationService.createInvitation` to dispatch emails.
    - Update `Invitation` model if a secure token is needed (or use the UUID).
