# Bug Report: BUG-006 - Backend Supabase Auth SSL Verification Failure

**Type**: Dependency issue
**Severity**: Critical
**Feature**: 001-calculoides-core-app
**Reported**: 2026-05-14
**Status**: Patched
**Patched**: 2026-05-14

## Description
The backend server fails to authenticate users because it cannot verify the SSL certificate when communicating with the Supabase Auth API. This results in a `SELF_SIGNED_CERT_IN_CHAIN` error during the `getUser` call in the authentication middleware. Consequently, all protected API routes (e.g., `/api/groups`) return a `401 Unauthorized` error to the frontend, even if the user has a valid session in the browser.

## Root Cause Analysis
The issue is caused by Node.js's strict SSL certificate validation. In a local development setup (using `supabase start` or a local proxy), Supabase may use self-signed certificates. While browsers can be told to trust these, the Node.js `fetch` implementation (via `undici` in recent Node versions) rejects them by default. This prevents the backend from validating the session token passed by the frontend.
